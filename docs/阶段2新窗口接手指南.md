## 2. 让方法二以后能接入的最低条件

下列是实现约束和建议设计，本轮不编写预算算法、通用插件框架或第二套索引。

1. **保留完整页面特征。** 原编码器输出完整`[1031,128]`；D使用其中前1024个视觉patch。预算检索表示另存，不能覆盖完整特征，也不能把变短序列直接传给D。统计成本时完整缓存不能隐去。
2. **固定页面检索边界。** 输入仍是本次真实query表示、数据库授权范围、索引代和k；输出是可回溯的page ID、排名、分数与配置身份。预算策略的选择/分配不要写进登录、上传路由或前端。
3. **记录预算与语料身份。** 明确预算单位、分配范围、总预算、每页分配和是否需要整库统计；保存算法/编码器/评分/语料版本。新增、删除或替换PDF后，按研究算法决定重算哪些分配，不能假设永远只改一页。
4. **用新索引代适配与切换。** 若仍使用相同128维多向量和MaxSim，可在既有检索模块扩展；维度、query处理或评分改变时需要新adapter/校验，不能套用旧身份。只改预算且完整编码身份不变时可复用完整特征；否则重新核验是否需要编码。
5. **授权和验收独立保留。** 过滤必须在Top-k之前；新策略通过预算约束、页面映射、参考分数、隔离、删除/恢复、成本与效果检查后才激活，旧完整向量基线可回退。不能以“可返回结果”宣称研究有效。

方法二接入的建议流程：**冻结研究实现与输入输出 → 在同一完整页面库建新配置/索引代 → 与基线对照 → 权限与失败回归 → 激活并保留回退**。预计改动集中在检索策略、索引与配置层；具体工作量取决于届时算法接口，不承诺零改动。
