## 2. 所有阶段共同遵守的规则

- 只改独立`layoutpatch-system`；旧`layoutpatch`、`layoutpatch-evidence`、`Snappy`只读。不下载模型、不训练、不换底座、不覆盖旧研究结果，不擅自暂存、提交或推送。
- 复用原ColPali、既有D-no-text身份及已核实的Snappy工程机制；新增代码说明来源。身份、坐标或评分不一致先定位，不降低阈值或换模型掩盖失败。
- 每批先检查实际代码、依赖、端口和数据，再备份受影响状态；历史PID、报告、计划不等于当前运行结果。开发验收使用隔离数据，正式数据变更需在该批明确范围。
- 后端以当前会话和数据库归属决定权限；上传owner由服务端决定。任务、图片、区域、历史、文件均须独立鉴权，不能只隐藏按钮。
- 测试替身可验证错误路径，但真实页面编码、问题编码、解析与区域推理必须另留真实证据。错误、空结果、超时要明确显示，不能回放旧结果或编造框。
- 每批交付“目的、改动、检查、失败/阻塞、口述、下一唯一任务”，随后停止。日期和批次编号固定，不以一次对话打包完成整个阶段。

## 3. 阶段2：新PDF入库与证据定位

建议分六批，按顺序推进。阶段出口是“**新PDF → 全页入库 → 实际新问题 → 授权Top-k → 真实候选证据高亮**”，不是仅让网页出现上传按钮。

### 2-1｜新PDF上传、归属与持久任务基础

- **目的：**把一份新文件变成有主人、有版本、有处理状态的系统对象。
- **任务：**核对现有表与接口设计；增量迁移所缺字段；实现受保护的PDF上传与任务状态查询。检查格式、可解析性及明确配置的大小/页数上限；服务端生成ID与受控路径、记录哈希和版本，默认private，不接受客户端指定他人owner。保存任务、attempt和错误状态；异常写入不得留下可检索的半成品。
- **实现注意：**现有写接口仅接收JSON，multipart上传须针对该路由扩展，同时保留Origin/CSRF与首次改密门禁；不全局关闭保护。现有PNG预览约束`runtime/corpus`，上传/渲染路径须纳入受控方案，不能公开静态目录。
- **验收：**A/B同名不同内容的PDF分别归属本人；未登录401、跨用户任务/文档不可读；伪PDF、超限、写盘失败明确拒绝；服务重启后文件元数据与任务仍在，重复请求策略有测试。新任务尚未完成时不进入搜索。覆盖T01/T03/T05/T09适用子项。
- **边界：**本批可停在queued，不承诺完成页面编码、MinerU、D或上传网页。确切上传字段、限额和重试标识在本批检查后定稿，不能写成现有接口。

### 2-2｜完整页面渲染、编码与索引安全激活

- **前置：**2-1完成；先决定当前profile/index如何接纳增量文档，记录事务与失败恢复方案。
- **任务：**将新PDF全部页面渲染成原图，记录页码、尺寸、渲染身份与哈希；用原ColPali真实编码，保存完整页面特征，写入匹配profile的Qdrant索引。页面编码和query编码共享单份模型并串行执行；新增页数不能硬编码为13。
- **实现注意：**现有搜索检查唯一ready索引、完整页面及实际点数。元数据、索引和激活状态必须协调；暂存中间数据不能导致已有13页查询整体失败。全部完成并校验后才切换为可搜索，失败仍保留旧的有效索引范围。
- **验收：**新PDF全部页数/哈希/向量身份一致；有效query token、完整1031×128特征及1024视觉patch规则保持；用实际新问题与官方参考核对同一授权范围的分数/排名。模拟中途编码和写库失败，半成品不可搜、旧文档仍可用。覆盖T03/T06/T09，并扩展T11基线对照。
- **边界：**此时只完成页面检索，不宣称已有证据区域；不为演示重新导入旧13页掩盖持久化问题。

### 2-3｜上传与任务网页、恢复和重试

- **前置：**2-2完整页面链路可用。
- **任务：**提供本人文档、上传、任务状态/失败原因页面；接入真实API与SDK。增加有界等待、取消检查点、重启后interrupted状态和显式重试；每次attempt可追踪，不重复激活页面。
- **验收：**用户从网页上传新PDF后，用实际新问题得到Top-k和授权原图；A/B内容隔离；失败可见、重试可恢复、取消后不会迟到激活；重启不把半成品变ready；换号与旧请求清理保持。覆盖T01/T03/T06/T09/T14适用子项。
- **边界：**新PDF页面闭环到此验收；解析及区域仍未完成。先让页面检索独立可用，后面的解析故障不能抹掉它。

### 2-4｜真实MinerU解析与坐标契约

- **前置：**新PDF和稳定页面身份可用。
- **任务：**核查已有MinerU及本地解析模型，在独立解析环境实际运行；记录版本、来源和哈希，输出每页候选ID、类型、bbox、坐标系和解析版本，映射到同版原图像素坐标。
- **验收：**对新PDF真实解析并抽查图/表/文字候选与页码；坐标有限、范围合法、来源可追踪。无候选、解析异常、超时分别有状态；仍可查看检索页。覆盖T07/T08相关子项。
- **边界：**“依赖和模型文件存在”不等于解析通过。缺已有离线依赖或模型时记录阻塞，不自行下载、不用手工框冒充解析输出。

### 2-5｜D-no-text真实推理适配

- **前置：**2-4候选、坐标和页面身份稳定。
- **任务：**按既有[算法接口](interfaces.md)固定seed0 / epoch1身份；核对checkpoint与必要算法代码来源。先用冻结开发缓存对照迁移前后的候选ID、P′、分数及排序，再对新PDF候选执行真实推理；完整页面特征和区域派生特征分别管理。
- **验收：**权重严格加载且哈希一致，真实forward有记录；新问题使用本次真实query特征，不从预测表或gold构造输入。数值、近似并列和容差在测试前固定，异常或非有限分数不进入响应。覆盖T12及T07/T08适用子项。
- **边界：**不训练、不用外部结果选最好seed、不把缓存一致性当作新PDF区域效果已达标。真实候选无法接入时报告核心阻塞。

### 2-6｜授权区域接口、高亮与阶段2整体验收

- **前置：**2-5真实区域输出可用。
- **任务：**区域响应绑定document/page/render/候选/model版本；逐次授权，前端叠加原图像素框，显示证据类型与状态。保留检索页与区域失败状态，换号/退出/过期清除旧区域。
- **验收：**完成新PDF上传→全页入库→新问题→Top-k→真实区域完整演示；50%/100%/150%缩放框位置一致，页码/类型/ID对应；A不能读取B的区域或裁剪。解析/区域失败不妨碍原图，重启与撤销会话仍正确。登记T01/T03/T06—T09/T11/T12的实际覆盖，不提前宣布整表通过。
- **阶段出口：**保存真实截图、样例/输入身份、成功及失败报告、未解决限制。只有页面检索通过而区域未通时，记为阶段2部分完成。

## 4. 阶段3：管理与业务完整性

以下五批默认顺序执行；基础任务恢复已在阶段2实现，不拖到管理页面完成才处理。

| 批次 | 主要任务 | 可检查的完成条件 |
|---|---|---|
| 3-1 用户管理 | 管理员账号列表、建号、停用、重置密码；复用已有认证CLI背后的业务规则，保护最后管理员 | 普通用户构造管理HTTP请求仍403；重置/停用后旧会话失效；本人首次改密路径完成。T02/T05 |
| 3-2 共享发布与撤回 | 管理员发布/撤下共享文档；确定跨用户管理的显式范围、二次确认及审计，普通用户仅管理本人资料 | A/B可检索共享，不能执行其管理任务；撤回后旧结果关联的图片/区域/历史请求重新拒绝。管理员普通搜索仍无全库private旁路。T02—T05 |
| 3-3 完整删除与清理重试 | 先撤销可访问状态，再清索引、原文件、页图、候选、派生特征与缓存；保留可重试的失败任务 | 删除中即不可检索/预览；模拟清理失败仍不可读；重试幂等，不误删另一用户同名文档。T03/T09/T10 |
| 3-4 检索历史、任务与审计记录 | 本人历史；管理员在明确授权范围查看操作和失败记录；记录操作者、对象、时间、结果，规定保留范围 | 历史按当前权限过滤，撤回/删除后不能通过历史绕行；日志不含密码、Cookie、CSRF、密钥，查询原文的访问/脱敏规则落实。T01/T03/T04/T14 |
| 3-5 配置身份、重建与回退 | 管理不可变profile、验证状态与索引代；切换前检查，失败保留旧代；记录完整特征及索引成本 | 身份不符拒用；后台配置、实际模型与页面显示一致；重建/切换/失败回退有实测。T02/T13/T14 |

**预算方法边界：**只有上游已有有效实现、冻结身份和对照证据，才在3-5接入。未就绪则保持`colpali_full_v1`，界面和论文明确“完整向量基线”；接入预算方法不是本系统自动获得的研究结论，也不授权新训练或换底座。

**阶段出口：**用户与管理员核心操作有页面和后端保障；共享撤回、删除、旧会话、历史访问与索引切换相互一致。实时撤权推送、大规模并发或复杂后台美化不作为未经讨论的新增承诺；已传给浏览器的图片字节无法远程收回。
